# План реализации: локальный транскрибатор с маскированием ПД

Основа — ТЗ от 12.10.2026. Оценки даны для одного разработчика. Порядок внутри этапа задан так, чтобы самые рискованные вещи проверялись первыми.

## 1. Структура репозитория

```
local_asr_and_masking/
  pyproject.toml            # uv, Python 3.11; extras: [asr], [ui]
  NOTICE                    # лицензии и атрибуция pyannote (CC-BY-4.0)
  src/transcriber/
    model.py                # Utterance, Transcript, Span, Entity, Mention, Case
    config.py               # пути, типы ПД для маскирования, офлайн-переменные окружения
    logging.py              # фильтр, который не пропускает текст в логи
    audio/decode.py         # PyAV → float32 16 кГц моно + исходные каналы
    audio/vad.py            # Silero VAD (sherpa-onnx), нарезка до 30 с
    asr/base.py             # протокол AsrEngine
    asr/gigaam.py           # GigaAM v3 e2e_rnnt через onnx-asr
    asr/tone.py             # T-one
    diar/stereo.py          # разведение по каналам + проверка, что каналы различаются
    diar/sherpa.py          # pyannote-сегментация + 3D-Speaker
    importers/              # txt, md, docx, srt, vtt + определение кодировки
    normalize/numbers.py    # числа словами → цифры («восемь девятьсот…»)
    pii/rules/              # phone, email, card, account, passport, snils, inn, birthdate, code
    pii/checksums.py        # Луна, СНИЛС, ИНН-10/12
    pii/ner.py              # Natasha/slovnet NER + правило ОПФ + пользовательский словарь
    pii/morph.py            # падеж и пол по контексту (slovnet morph), лемма
    pii/cluster.py          # кандидаты на объединение (Левенштейн ≤ 2 + контекст)
    pii/detect.py           # оркестрация: склейка реплик, слияние и разрешение пересечений спанов
    mask.py                 # спаны → метки, словарь дела, идемпотентность
    unmask/parser.py        # толерантный парсер меток
    unmask/inflect.py       # склонение ФИО и названий через pymorphy3 + эвристики фамилий
    unmask/restore.py       # подстановка, «[неизвестное значение]», отчёт о подсветке
    export/docx.py          # шапка, инструкция, реплики, очистка core_properties
    export/md.py
    store/                  # шифрованная база: дела, словари, транскрипты, задачи
    jobs.py                 # фоновые задачи вне сессии UI, прогресс в БД
    cli.py                  # transcriber mask | unmask | transcribe | import | eval
    ui/                     # этап 3
  tests/
    unit/                   # синтетика, без реальных ПД
    golden/                 # пары «текст → маска → ответ Claude → демаска»
  eval/                     # скрипты метрик; данные лежат вне репо
  install/                  # install.sh, uninstall.sh, шаблон .app, install.ps1
```

Ключевые типы:

- `Span(start, end, type, value, source, confidence, case=None)` — находка в тексте транскрипта. Координаты считаются по склеенному тексту, обратная привязка к репликам идёт через таблицу смещений.
- `Entity(case_id, type, n, canonical, gender, variants[])` — одна сущность дела. Номер `n` сквозной по типу внутри дела.
- `Mention(entity, utterance_id, start, end, grammatical_case, flagged)` — одно упоминание.

Ядро — чистые функции поверх этих типов, без глобального состояния. Хранилище подключается через интерфейс, поэтому CLI и тесты работают с JSON-словарём, а приложение — с шифрованной базой.

## 2. Этапы и задачи

### Этап 1. Тестовый набор и выбор ASR (1 неделя по ТЗ, реально 2–3)

1. Формат разметки: JSONL с репликами и спанами ПД (тип, значение, падеж). Короткая инструкция для разметчика.
2. Каркас репозитория, uv, `ruff`, `pytest`, CI на GitHub Actions с раннерами `macos-14` (arm64) и `ubuntu`.
3. `audio/decode.py` и `audio/vad.py` — понадобятся для сравнения движков.
4. Обёртки GigaAM v3 и T-one и скрипт `eval/asr.py`: WER, доля верно распознанных фамилий, RTF на M1 8 ГБ.
5. Сразу проверить: есть ли у `onnx-asr` готовый ONNX GigaAM v3 `e2e_rnnt` и укладывается ли RTF в бюджет (≤ 0,1, чтобы час записи распознавался за ~6 минут и оставалось время на диаризацию).

**Готово:** выбран движок по умолчанию, базовая линия WER и распознавания фамилий записана в `eval/BASELINE.md`.

### Этап 2. Ядро в CLI (2–3 недели по ТЗ, реально 3–4)

Порядок задан по риску. Сначала обратимость и падежи, потому что на них держится вся схема.

**Неделя 1 — маскирование текста и демаскирование.**

1. `model.py`, JSON-хранилище словаря дела.
2. `pii/rules` и `checksums`: телефон, email, карта, счёт, паспорт, СНИЛС, ИНН, ДР, коды. За основу берётся pii-mask. Юнит-тесты на каждое правило, включая числа, продиктованные группами и с перебивками.
3. `normalize/numbers.py`. Это отдельная мини-задача: «восемь девятьсот шестнадцать сто двадцать три сорок пять ноль семь» должно превратиться в цифры с сохранением группировки.
4. `pii/ner.py` и `pii/morph.py`: Natasha NER (PER, ORG, LOC), падеж и пол по контексту предложения, нормальная форма через лемматизацию slovnet и pymorphy3.
5. `mask.py`: разрешение пересечений спанов (правила важнее NER, длинный спан важнее короткого), метки с падежом, неопределённый падеж → `им` и флаг, идемпотентность через белый список меток и масок.
6. `unmask/parser.py`: все искажения из ТЗ, а также полноширинные скобки, экранирование `\[ФИО\_1\]` в markdown и `[ФИО_1:Дат.]`.
7. `unmask/inflect.py`: склонение каждого слова ФИО с учётом пола. Эвристики для фамилий вне словаря (-ов/-ев/-ин/-ский/-цкий/-ая), список несклоняемых (-ко, -их/-ых, -аго, иностранные на гласную, женские фамилии на согласную).
8. `unmask/restore.py`: телефоны и email сопоставляются по цифрам; падеж для метки без кода определяется по предлогу и управлению глагола; на выходе — текст и список спанов для подсветки.
9. `transcriber mask` / `transcriber unmask` поверх txt.

**Неделя 2 — импорт, экспорт, кластеризация.**

10. `importers/`: определение кодировки (UTF-8 → CP1251 через `charset-normalizer`), шаблоны спикеров, таймкоды srt/vtt, имена спикеров проходят через детектор, роль остаётся.
11. `pii/cluster.py`: предложения на объединение, без автоматического слияния.
12. `export/docx.py` и `md.py`: шапка с кодом дела, инструкция для Claude, формат `Спикер [00:12:30]: текст`. Очистка всех полей `core_properties` (author, last_modified_by, title, subject, keywords, comments, category, created, modified, revision). Тест открывает docx как zip и ищет все значения ПД во всех XML-частях.
13. Сбой любого шага → исключение, файл не создаётся. Запись идёт во временный файл и атомарно переименовывается.

**Неделя 3 — аудио-конвейер.**

14. `diar/stereo.py` (корреляция каналов как критерий «различаются») и `diar/sherpa.py`, затем сопоставление сегментов диаризации с репликами ASR.
15. `transcriber transcribe audio.m4a --speakers auto` — полный путь до docx.
16. `jobs.py`: задача в отдельном процессе с прогрессом в секундах записи. Временные файлы — в каталоге с правами 700, удаление в `finally`.
17. Замер скорости на M1 8 ГБ на часовом звонке.

**Неделя 4 — метрики.**

18. `transcriber eval`: полнота по типам, доля верных падежей, обратимость на golden-наборе. В golden-набор входят 20 реальных ответов Claude по замаскированным тестовым транскриптам.
19. Доводка правил и эвристик до порогов.

**Готово:** полнота форматных ПД ≥ 95%, ФИО и организаций ≥ 90%, обратимость 100%, падеж при маскировании ≥ 95%, при демаскировании ≥ 90%, идемпотентность и устойчивость к переформатированию телефонов покрыты тестами.

### Этап 3. Интерфейс и хранилище (2 недели)

1. Два спайка по 1–2 дня: UI-фреймворк (пункт 4 раздела 0) и шифрование базы (пункт 5).
2. `store/`: схема — дела, сущности, упоминания, транскрипты, задачи, настройки. Пароль при первом запуске, Argon2id, ключ живёт только в памяти. Удаление дела: перезапись записей, затем `VACUUM`. Автоудаление по сроку при старте.
3. Экраны: список дел, загрузка (аудио или транскрипт, число спикеров), прогресс, проверка, экспорт, «Вернуть данные», настройки, «О программе», «Выключить».
4. Экран проверки: подсветка по типам, снятие маски кликом, добавление выделением, объединение сущностей, отдельный блок для низкоуверенных находок и упоминаний с флагом падежа, чекбокс «Я проверил».
5. Офлайн: `HF_HUB_OFFLINE=1`, `GRADIO_ANALYTICS_ENABLED=False`, `share=False`, никаких шрифтов и скриптов с CDN. Тест запускает полный цикл под сетевым монитором. Для CI — pytest-socket, который запрещает сокеты кроме 127.0.0.1.
6. Время запуска ≤ 10 с: модели грузятся лениво или в фоне после открытия вкладки.

**Готово:** полный цикл проходит без терминала, монитор сети показывает 0 соединений.

### Этап 4. Установка на macOS (1 неделя)

1. `install.sh`: uv → `uv tool install` → модели с SHA-256 из манифеста → `.app` в `/Applications` или `~/Applications` → запуск. Каждый шаг идемпотентен.
2. Запускалка `.app`: AppleScript или shell-бандл, собирается на машине пользователя, поэтому карантинного атрибута нет. Если сервер жив (проверка через `/health` на 127.0.0.1), запускалка только открывает вкладку.
3. «Проверить обновления»: манифест версии кода и моделей, `uv tool upgrade`, догрузка только изменившихся моделей.
4. `uninstall.sh` спрашивает, удалять ли данные.
5. Прогон на чистом маке (VM или выделенная учётка без прав администратора) с замером времени.

**Готово:** установка на чистом маке занимает ≤ 10 минут и проходит без ошибок.

### Этап 5. Качество (2–4 недели)

1. Разметка дополнительных звонков (не из приёмочного набора!) и дообучение ruBERT NER на PyTorch вне продукта, экспорт в ONNX и подключение через `pii/ner.py`.
2. Опциональный LLM-аудитор на локальной модели: ищет пропущенные ПД и подсвечивает их на экране проверки, сам не маскирует.

## 3. Сквозные требования, которые проверяются с первого коммита

- **Логи.** Единый фильтр в `logging.py` и тест, который прогоняет конвейер на синтетических ПД и ищет их значения в логах.
- **Сеть.** pytest-socket во всех тестах.
- **Лицензии.** `NOTICE` обновляется вместе с каждой новой зависимостью или моделью.
- **Платформы.** Ядро без macOS-специфики. Пути через `platformdirs`, поэтому Windows и Linux на следующем этапе потребуют в основном установщиков.
